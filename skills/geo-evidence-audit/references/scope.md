# Scope / 与相邻 skill 的分工

novera-skills 产品线是"Trust layer for AI agents"。geo-evidence-audit 只
负责其中一格：**文本资产中地理声称的自洽性审计**。以下分工避免触发场景重叠。

## 分工表

| 相邻 skill | 职责边界 | 与本 skill 的关系 |
|-----------|---------|------------------|
| **skill-sentry**（已发布，独立仓库） | 本地运行时审计：对运行中的代码/进程行为做安全审计 | 不重叠：sentry 管"代码与运行时"，本 skill 管"文档与数据资产中的地理声称"。用户要求"审计代码安全"时不触发本 skill |
| **skill-supply-chain-audit**（novera-skills #4，规划中） | 来源侧供应链画像：依赖、包来源、许可证画像 | 不重叠：管"东西从哪来"，不管"办公室在哪"。本 skill 的 When NOT to use 已显式引用 |
| **api-spec-generator**（已发布，独立仓库） | API 规范的生成与规范化 | 不重叠：API 契约与地理声称无关；API 文档若含地理声称（如"服务器位于新加坡"），其文本部分可由本 skill 审计，但 spec 结构校验归 api-spec-generator |
| **pii-signal-scanner**（已发布，独立仓库） | 隐私信号检测：PII / 个人数据识别 | 边界案例：地址、坐标既可能是地理声称也可能是 PII。用户意图是"找个人信息泄露" → pii-signal-scanner；意图是"查地理信息自洽" → 本 skill。两个 skill 可先后独立运行 |
| **monorepo-analyzer**（已发布，独立仓库） | 仓库整体结构分析 | 不重叠：结构分析不涉及地理声称 |

## 本 skill 明确不做的事（红线）

1. 不做真值核实：不判断"办公室/门店是否真实存在"，不联网；
2. 不做精确反地理编码：只有国家级粗粒度 bbox 外包框校验；
3. 不做 IP 归属地核查（"服务器位于新加坡"这类声称 v0.1 只按 R7 标注
   unverified，不内置 IP 段表；是否在 v0.2 引入离线 IP 库另行评估）；
4. 不修改用户文件，只输出报告；
5. 不承诺其他语种（中英文之外的词表覆盖未验证，宁漏报不误报）。

## 判定口诀

- 问"这些地理信息互相矛盾吗 / 有没有佐证" → **本 skill**
- 问"这地方真实存在吗 / 这个坐标在哪个街道" → 不触发（真值/精确反地理编码）
- 问"这段代码/依赖/规范/隐私安全吗" → 对应相邻 skill
